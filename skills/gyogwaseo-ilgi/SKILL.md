# 교과서 읽기 (kordoc)

PDF와 한글 파일은 그대로 읽으면 표가 깨지고 읽는 순서가 뒤섞인다. 수업을 설계하기 전에
[kordoc](https://github.com/chrisryugj/kordoc)으로 **필요한 쪽만** 마크다운으로 바꿔 읽는다.

```
목차 찾기 → 단원 쪽 뽑기 → (스캔본이면 OCR) → 교과서.md → suup-jejak으로 수업 설계
```

## 1. 명령

필요한 것: Node.js 20 이상. 처음 실행할 때 인터넷에서 kordoc을 내려받는다(설치할 것 없음).
먼저 `node --version`으로 확인한다. Node가 없거나 20보다 낮으면 kordoc을 쓰지 않고 4장을 따른다. Node를 설치하자고 하지 않는다.

```
npx -y kordoc@4 <파일> --pages 1-12 -o <차시폴더>/목차.md          # 앞쪽 목차
npx -y kordoc@4 <파일> --pages 34-41 -o <차시폴더>/교과서.md       # 단원 쪽만
npx -y kordoc@4 <파일> --pages 34-41 --format json -o <차시폴더>/교과서.json   # 품질 확인용
npx -y kordoc@4 <파일> --pages 34-41 --ocr -o <차시폴더>/교과서.md # 스캔본
```

- 지원 형식: PDF, HWP, HWPX, DOCX, XLSX, PPTX, 사진(PNG, JPG 등. 사진은 OCR이 저절로 켜짐).
- `--pages`는 **PDF 파일의 쪽 순서**다. 교과서에 인쇄된 쪽 번호와 다를 수 있으니(표지·목차만큼 밀림) 목차.md의 쪽 번호와 한 쪽을 뽑아 맞춰 본 뒤 범위를 정한다.
- Windows PowerShell에서 `npx`가 실행 정책 때문에 막히면 `npx.cmd`로 부른다.
- 결과 파일은 사용자의 차시 폴더에 둔다(스킬 폴더 안에 두지 않는다). 원본 교과서 파일은 옮기거나 고치지 않는다.

## 2. 순서

### ① 범위 정하기
- 사용자가 쪽이나 단원을 말했으면 그 범위만 뽑는다.
- 말하지 않았으면 앞쪽 12쪽 정도로 목차를 읽고, 성취기준·단원에 맞는 쪽을 찾아 사용자에게 밝힌다.
- **교과서 전체를 한꺼번에 바꾸지 않는다.** 200쪽이 넘는 PDF는 오래 걸리고, 읽을 양만 늘어난다. 한 차시에는 보통 2~8쪽이면 된다.

### ② 품질 확인
- `--format json`의 `qualitySummary.needsOcr`가 `true`이거나, 마크다운에 글이 거의 없거나 깨진 글자(□, �)가 많으면 스캔본이다. `--ocr`을 붙여 다시 뽑는다. 처음 OCR을 쓸 때 모델(약 18MB)을 내려받는다.
- 그림 속 글자(그래프 눈금, 삽화 설명)는 빠질 수 있다. 수업에 중요한 그림이면 사용자에게 어떤 그림인지 묻는다.
- 수식이 많은 쪽(수학, 물리)에서 식이 깨지면 `--formula-ocr`을 쓴다(처음에 모델 약 155MB를 내려받음). 쓰기 전에 사용자에게 알린다.

### ③ 수업 설계에 쓰기
교과서.md를 읽은 뒤 suup-jejak 스킬로 넘어가 design.json을 쓴다. 이때:

| 교과서에서 가져올 것 | 어디에 쓰나 |
|---|---|
| 대단원·소단원 이름 | `meta.unit`, `meta.subunit` (교과서의 이름을 그대로) |
| 핵심 용어와 정의 | 개념 정리 문항, 빈칸 채우기 |
| 탐구·활동 과정 | 전개 활동의 순서 |
| 예시, 자료, 사진 설명 | 동기 유발, `자료:` 줄 |
| 단원 끝 문제 | 스스로 점검, 형성 평가 문항 (다듬어서) |

- 성취기준은 그대로 suup-jejak의 `standards context`(Windows는 `suup.ps1`, 그 밖은 `standards.mjs`)로 확인한다. 교과서는 **어떻게** 가르칠지, 성취기준은 **무엇을** 확인할지의 근거다.
- 어느 교과서 몇 쪽을 썼는지 `plan_note`에 적는다. 예: `○○출판사 과학 3, 34~41쪽을 바탕으로 함`.
- 교과서 문장을 활동지에 길게 옮겨 적지 않는다. 교과서는 저작물이므로 핵심 용어와 짧은 인용만 쓰고, 문항은 학생에게 하는 말로 새로 쓴다.

## 3. 안 될 때

- `npx`를 찾을 수 없음: Node.js가 없다. 4장을 따른다.
- 인터넷이 막힌 곳: 미리 `npm install -g kordoc`으로 설치해 두고 `kordoc <파일> …`로 부른다. 자세한 것은 kordoc의 폐쇄망 설치 안내를 본다.
- 암호가 걸린 PDF나 DRM이 있는 전자 교과서는 읽지 못할 수 있다. 사용자에게 해당 쪽을 PDF로 저장하거나 사진으로 찍어 달라고 한다.

## 4. Node.js가 없을 때: AI가 PDF를 직접 읽기

kordoc 없이 AI 앱의 파일 읽기로 PDF를 직접 읽고 분석한다. 따로 설치하거나 파싱하지 않는다.

- 2장 순서는 그대로다. 앞쪽 목차를 읽어 단원 쪽을 찾고, **필요한 쪽만** 읽는다. 예: Claude Code는 PDF를 쪽 범위로 읽는다(한 번에 20쪽까지, 10쪽이 넘는 PDF는 쪽 범위를 정해야 함).
- 읽은 내용 가운데 수업에 쓸 것(단원명, 핵심 용어와 정의, 활동 과정, 단원 끝 문제)을 `<차시폴더>/교과서.md`에 쪽 번호와 함께 정리한다. 그다음 2장 ③과 같이 수업 설계에 쓴다.
- 표, 빈칸, 수식은 글로 옮길 때 틀리기 쉽다. 수업에 중요한 표나 식은 쪽 그림을 보고 다시 확인하고, 애매하면 사용자에게 맞는지 묻는다.
- 스캔본도 쪽을 그림으로 보고 읽는다. 글자가 흐려 읽기 어려우면 사용자에게 알린다.
- **HWP·HWPX 파일**은 직접 읽지 못한다. 사용자에게 한글에서 필요한 쪽을 PDF로 저장(파일 → PDF로 저장)해 달라고 한다.
- AI 앱이 PDF를 읽지 못하면 사용자에게 필요한 쪽을 사진(PNG, JPG)으로 찍거나 글을 복사해 붙여 달라고 한다.
